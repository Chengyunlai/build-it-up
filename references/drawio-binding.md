# Mermaid 与 draw.io 绑定

这是一份适配指南，不代表环境一定安装了 draw.io 连接器。先检查当前环境能否操作用户的 draw.io 桌面版或 diagrams.net 网页版，只使用实际可用的能力。

## 统一身份

只有在 issue 获得明确确认并成功发布后，才能根据 issue 标题生成稳定 slug：

`<issue-key>__<short-kebab-case-title>`

如果客户端支持，在 draw.io 文件名、文档标题、顶层页面和图表元数据中统一使用这个身份。根据 issue 分类（`feature`、`bug`、`refactor`、`design`、`research` 或 `chore`）给页面分类。如果 tracker 支持标签，只有链接确实建立后，才能添加相同的分类标签和 `diagram-linked` 标签。

## 图表类型映射

- 用户旅程或分支行为 → 流程图。
- 服务之间的调用或事件顺序 → 时序图。
- 生命周期、状态或权限 → 状态图。
- 模块和依赖关系 → 组件图。
- 数据实体和关系 → ER 图。

确认前，Mermaid 源码是可评审的事实基准。修改时保持节点标识稳定，方便针对具体节点反馈。绑定后仍要把 Mermaid 代码块保留在 issue 或其关联产物中，确保图表可迁移。

## 网页版 draw.io 流程

浏览器控制能力可用时：

1. 打开 diagrams.net；如果用户已有登录会话，使用该会话。
2. 创建或打开以统一身份命名的文档。
3. 使用网页端支持的导入方式导入或重建已确认的 Mermaid 图，并进行视觉检查。
4. 使用 issue key 和分类命名页面；如果应用允许，在图中加入包含 issue URL/key 的小文本说明。
5. 把 draw.io URL 回填到 issue；如果 tracker 支持评论或链接，再把 issue URL/key 回填到图中。
6. 报告准确 URL 以及已经验证的内容。

## 桌面版 draw.io 流程

computer-use 能力可用时：

1. 打开桌面应用，在用户确认的位置创建或打开文档。
2. 使用相同的统一文件名、页面名和分类。
3. 导入或重建已确认的 Mermaid 图，并检查布局、标签和连接线。
4. 保存后取得真实本地路径，并将其写入 issue。本地路径不是可分享 URL，要明确说明这一点。

## 降级方案

如果两个 draw.io 客户端都无法控制，不要模拟已经完成。返回已确认的 Mermaid 源码、建议的统一文件名和页面名、issue key/分类，以及导入和添加双向链接的简明手工步骤。如果 issue 本身无法发布，issue 和图表都要明确标记为本地草稿。

## 安全与真实性

没有检查路径前，不要覆盖已有 draw.io 文件；目标不明确时先请求确认。对应文档实际存在前，不要添加 tracker 标签或链接。如果 tracker 或 draw.io 客户端不支持双向链接，就记录单向链接和具体限制。
